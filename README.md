# Chat Handoff — инструкция по использованию

Claude скилл `chat-handoff` используется для переноса контекста и превращает текущий чат в готовый markdown-блок, который вставляется первым сообщением в новый чат. Новый Claude мгновенно получает рабочий контекст, без переспросов и без раздутой истории.

---

## 1. Установка

### - Вариант с Claude.ai

- Скачай репозиторий как архив ZIP
- Перейди **claude.ai → Sidebar → Customize → Skills → Upload a Skill** и выбери архив

> После этого скилл доступен во всех новых сессиях Claude. Проверить установку **claude.ai → Sidebar → Customize → Skills → Upload a Skill**  — `chat-handoff` должен появиться в списке.

### - Вариант с Claude Code

Клонируй репозиторий напрямую в папку скиллов Claude Code

```bash
mkdir -p ~/.claude/skills
git clone https://github.com/Leonid74/ai-skill-chat-handoff.git ~/.claude/skills/chat-handoff
```

> После этого скилл доступен во всех новых сессиях Claude Code. Проверить установку можно командой `claude /skills` — `chat-handoff` должен появиться в списке.

---

## 2. Триггерные фразы

Скилл срабатывает автоматически, как только распознаёт намерение «закрыть текущий чат и перенести контекст». Все фразы ниже эквивалентны — выбирай любую удобную:

### Основные (русский)

- «суммаризируй чат»
- «суммаризируй диалог»
- «передай контекст в новый чат»
- «сделай хэндоф»
- «выжимка диалога»
- «контекст для нового чата»
- «продолжим в новом чате»
- «перенос в новый чат»

### Основные (английский)

- «handoff»
- «summarize this chat»
- «wrap up this session»
- «hand off context to a new chat»

### Косвенные (тоже сработают)

- «давай завершим эту сессию»
- «закругляемся в этом чате»
- «мне нужна выжимка для следующего разговора»

Если по какой-то причине скилл не сработал — добавь явное «используй chat-handoff» или повтори фразу с ключевым словом «handoff» / «контекст для нового чата».

## 3. Модификаторы результата

Триггерная фраза определяет, **что** сделать, а модификатор — **в каком формате**. Добавляй модификатор к триггерной фразе одной строкой.

### Дефолтный режим

Просто триггерная фраза без модификаторов:

> - «Суммаризируй чат»
> - «Сделай хэндоф»
> - «handoff» и т.д.

Получаешь полный шаблон со всеми релевантными секциями: TL;DR, Запомни, О чём был чат, Главное, Решения и почему, Текущее состояние, Артефакты, Источники, Договорённости, Открытые вопросы + опциональные (Решённые проблемы, Альтернативы, Вне scope, Терминология, Ограничения, Цитаты).

**Когда использовать:** в большинстве случаев. Подходит для средних и длинных рабочих чатов.

### Компактный режим

Триггерная фраза + слово «коротко» / «компактно» / «кратко»:

> - «Сделай хэндоф коротко»
> - «Компактная выжимка диалога» и т.д.

Получаешь сокращённый шаблон: только TL;DR + О чём был чат + Главное + Открытые вопросы (+ Запомни, если в чате было tagged memory).

**Когда использовать:** короткий чат (менее ~10 содержательных реплик), однотемный диалог, ситуация «просто передай суть».

### Расширенный режим

Триггерная фраза + «развёрнуто» / «полный handoff» / «подробно»:

> - «Передай полный контекст в новый чат»
> - «Сделай хэндоф развёрнуто» и т.д.

Получаешь максимально полный шаблон со всеми опциональными секциями, даже если они малы. Включаются ключевые цитаты, терминология, ограничения, решённые проблемы.

**Когда использовать:** долгая работа над сложным проектом, передача контекста другому разработчику, архивирование рабочей сессии.

### Mixed-режим (определяется автоматически)

Если в чате обсуждались **2+ несвязанные темы** (например, дебаг CRM-интеграции + выбор хостинга), скилл сам определит это и разобьёт выжимку на самостоятельные мини-блоки по темам. Триггерную фразу можешь использовать любую — режим включится автоматически.

## 4. Что получаешь на выходе

Claude выдаст одну строку-инструкцию и **fenced markdown-блок** прямо в чат. Пример (дефолтный режим):

````markdown
# Контекст из прошлого чата

> Это передача контекста из предыдущей сессии. Прочитай молча. Ответь одним словом — «принял». Не пересказывай содержимое, не резюмируй, не задавай вопросов. Жди следующего сообщения с реальной задачей.

**TL;DR:** Дебажили выгрузку сделок из Bitrix24 в Excel-отчёт. Причина расхождений — не отфильтрованы стадии `LOSE` 
и `JUNK`.

## Запомни
- Никогда не агрегировать по `STAGE_SEMANTIC_ID = F` без явного запроса

## О чём был чат
Аналитический Excel-отчёт из сделок Bitrix24 расходится с эталонной выгрузкой клиента на 3 строки. Искали причину.

## Главное
- Расхождение — в учёте проигранных и отменённых сделок
- Bitrix REST API не фильтрует `JUNK`-стадии корректно через `filter[STAGE_ID]`
- Решение — постфильтрация в PHP после получения ответа

## Решения и почему
- **Фильтрация на стороне PHP, не Bitrix API** — потому что REST некорректно обрабатывает массив stage-ID для отказных стадий

## Текущее состояние
- Ветка `feature/excel-report`, незакоммичено: правка в `ReportBuilder::aggregateByStore()`
- Тесты на расхождение падают на 3 строках из 47

## Артефакты (файлы и пути)
- `src/Report/ReportBuilder.php` — основной агрегатор
- `tests/fixtures/reference_report.xlsx` — эталонная выгрузка клиента

## Открытые вопросы / следующий шаг
- Уточнить у клиента полный список исключаемых стадий
- Прогнать тесты после получения списка
````

## 5. Workflow использования

1. **В исходном чате** пишешь триггерную фразу (опционально с модификатором)
2. Claude выдаёт markdown-блок
3. **Копируешь блок**
4. **Открываешь новый чат** (`/clear` в Claude Code или новая сессия в Claude.ai)
5. **Вставляешь блок первым сообщением**
6. Новый Claude отвечает одним словом — «принял»
7. **Следующим сообщением пишешь реальную задачу:** «продолжаем — добавь обработку валютных сделок»

Новый чат сразу в курсе всего: целей, решений с обоснованиями, текущего состояния файлов, открытых вопросов и локальных договорённостей.

## 6. Когда применять

**Хорошие сценарии:**

- Контекст текущего чата разросся, ответы Claude замедлились или потеряли фокус.
- Большая задача разбита на этапы и между этапами нужна свежая сессия.
- Хочешь передать контекст коллеге (он откроет свой чат с этой выжимкой).
- Завершаешь рабочий день — хочешь зафиксировать состояние для возврата завтра.
- Скоро упрёшься в лимит контекста и нужно «перезагрузиться» без потери прогресса.

**Когда не нужен:**

- Чат короткий (1–3 реплики) — проще скопировать сам диалог.
- Контекст одноразовый и больше не понадобится.
- Уже есть полноценная документация в `CLAUDE.md` или комментариях к коду, покрывающая весь обсуждённый контекст.

## 7. Что НЕ делает скилл (важно)

- **Не вшивает новый запрос внутрь блока.** Выжимка — это read-only справка о прошлом. Реальную задачу для нового чата ты пишешь отдельным сообщением **после** вставки блока. Это намеренное архитектурное решение: иначе новый Claude получит контекст и тут же бросится «отвечать», хотя пользователь ещё не сформулировал реальный вопрос.
- **Не выдумывает.** Если причины какого-то решения в чате не было — скилл не пишет «потому что …», а называет решение без обоснования.
- **Не задаёт уточняющих вопросов.** Скилл одношаговый: триггер → выжимка.
- **Не пересказывает чат хронологически.** Только структурированные факты по секциям.
- **Не включает пустые секции.** Если в чате не было файлов — секции «Артефакты» в выжимке не будет.

## 8. Если что-то пошло не так

| Проблема | Решение |
|---|---|
| Скилл не сработал на триггерную фразу | Добавь «используй chat-handoff» явно |
| Выжимка слишком длинная | Используй модификатор «коротко» |
| Выжимка слишком короткая, упустила важное | Используй модификатор «развёрнуто» или укажи: «обязательно включи [тему]» |
| В блоке встречается что-то, чего не было в чате | Скилл не должен выдумывать — это баг. Напиши: «убери [N] — этого в чате не было» |
| Новый Claude в новом чате всё равно начинает пересказывать | Скажи ему: «просто скажи „принял“ и жди» |

## 9. Связанные команды

- `/clear` — очистить контекст в текущей сессии Claude Code (удобно после копирования handoff-блока)
- `claude /skills` — список доступных скиллов
- `claude /skills chat-handoff` — посмотреть содержимое скилла
